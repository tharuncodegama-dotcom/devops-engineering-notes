## 3. Swap Configuration

### Objective

Create a 4 GiB swap file and configure it to activate automatically after a server reboot.

### Commands executed

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

Added the following entry to `/etc/fstab`:

```fstab
/swapfile none swap sw 0 0
```

### Issue encountered

Attempted to append the swap configuration using:

```bash
sudo echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

This failed with `Permission denied` because the shell performs the `>>` redirection without elevated privileges.

### Solution

Used `tee` with `sudo`:

```bash
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Verification

```bash
free -h
swapon --show
```

Rebooted the server and verified that the swap file remained active.

**Result:**
- Swap file: `/swapfile`
- Swap size: 4 GiB
- Swap status: Active
- Persistence after reboot: Verified

### Key learnings

- `swapon` activates swap immediately.
- `/etc/fstab` configures swap for automatic activation during startup.
- `sudo` does not automatically elevate shell redirections.
- Swap provides disk-backed virtual memory but is not a replacement for sufficient physical RAM.

## 4. LVM Storage Management

### Objective

Use a separate 10 GiB disk to understand LVM physical volumes, volume groups, logical volumes, filesystems, and mount points.

### Step 1: Inspect the disk

```bash
lsblk
df -hT
sudo lsblk -f
sudo wipefs -n /dev/vdb
sudo pvs
```

Verified that `/dev/vdb` was a separate 10 GiB disk with no detected filesystem or LVM signatures.

### Step 2: Create the Physical Volume (PV)

```bash
sudo pvcreate /dev/vdb
sudo pvs
sudo pvdisplay /dev/vdb
```

**Result:** `/dev/vdb` was initialized as an LVM Physical Volume.

**Concept:** A Physical Volume is a disk or partition prepared for use by LVM.

### Step 3: Create the Volume Group (VG)

```bash
sudo vgcreate vg_data /dev/vdb
sudo vgs
sudo vgdisplay vg_data
sudo pvs
```

**Result:** Created the Volume Group `vg_data` with approximately 10 GiB of capacity.

**Concept:** A Volume Group combines the storage capacity of one or more Physical Volumes into a storage pool.

### Step 4: Create the Logical Volume (LV)

```bash
sudo lvcreate -L 6G -n lv_app vg_data
sudo lvs
sudo lvdisplay /dev/vg_data/lv_app
sudo vgs
```

**Result:**
- Logical Volume: `lv_app`
- Initial size: 6 GiB
- Remaining VG capacity: Approximately 4 GiB

**Concept:** A Logical Volume is a virtual block device allocated from a Volume Group. It can be formatted with a filesystem and mounted for application data.

### Step 5: Verify the filesystem

```bash
sudo blkid /dev/vg_data/lv_app
```

Confirmed the logical volume had an ext4 filesystem.

Filesystem UUID:

`42a42106-671d-44b0-8f52-80e88725f42b`

### Step 6: Mount the logical volume

Created the mount point and mounted the LV:

```bash
sudo mkdir -p /data
sudo mount /dev/vg_data/lv_app /data
```

An initial mount attempt failed because the device path and mount point were entered as one argument.

Correct syntax:

```bash
sudo mount DEVICE MOUNT_POINT
```

Verification commands:

```bash
df -hT /data
findmnt /data
```

**Result:**
- Filesystem: ext4
- Mount point: `/data`
- Access mode: Read-write
- Initial filesystem size: Approximately 5.9 GiB

### LVM architecture learned

```text
Physical Disk: /dev/vdb
        |
        v
Physical Volume (PV)
        |
        v
Volume Group (VG): vg_data
        |
        v
Logical Volume (LV): lv_app
        |
        v
ext4 Filesystem
        |
        v
Mount Point: /data
```

## 5. Extended the Logical Volume by 1 GiB

### Objective

Increase the logical volume from 6 GiB to 7 GiB while keeping the filesystem mounted.

### Command executed

```bash
sudo lvextend -L +1G -r /dev/vg_data/lv_app
```

### Command explanation

- `lvextend`: Extends a logical volume.
- `-L +1G`: Adds 1 GiB to the existing size.
- `-r`: Resizes the filesystem along with the logical volume.
- `/dev/vg_data/lv_app`: Target logical volume.

### Verification

```bash
sudo lvs
sudo vgs
df -hT /data
```

### Final results

| Component | Final result |
|---|---|
| Physical Volume | `/dev/vdb` |
| Physical Volume capacity | 10 GiB |
| Volume Group | `vg_data` |
| Logical Volume | `lv_app` |
| Final LV size | 7 GiB |
| Free VG capacity | Approximately 3 GiB |
| Filesystem | ext4 |
| Mount point | `/data` |
| Reported filesystem size | Approximately 6.9 GiB |
| Available filesystem space | Approximately 6.5 GiB |

**Result:** The logical volume was successfully extended by 1 GiB. The ext4 filesystem was also resized online without unmounting `/data`.

### Key learnings

- Extending an LV does not always expand the filesystem automatically.
- `lvextend -r` can extend both the logical volume and a supported filesystem.
- LVM allows flexible storage allocation and expansion.
- The Volume Group still has approximately 3 GiB available for future logical volumes.
