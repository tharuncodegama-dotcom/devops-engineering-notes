## 5. Security Concepts and Hardening Plan

Studied possible security measures for a VPS/dedicated-server hosting environment without relying on AWS infrastructure.

### Network and access security

- Restrict SSH access to approved IP addresses or VPN.
- Disable direct root SSH login after access validation.
- Continue using SSH public-key authentication.
- Consider Fail2ban.
- Configure UFW or nftables after reviewing existing network rules.

### Web application protection

- Consider Cloudflare WAF.
- Study ModSecurity with OWASP Core Rule Set.
- Protect public-facing domains and API endpoints.
- Validate uploaded files and prevent uploaded scripts from executing.
- Review application vulnerabilities and dependencies.

### Filesystem and repository protection

- Apply least-privilege permissions.
- Restrict application write access to source-code directories.
- Separate application uploads, logs, and source code.
- Use separate application service accounts where practical.
- Protect Git repositories and deployment credentials.

### Security monitoring

- Consider auditd for security event logging.
- Consider AIDE for file integrity monitoring.
- Study Wazuh for centralized security monitoring.
- Consider ClamAV for malware scanning.

## 9. Key Learnings

- SSH security and web application security are two different protection layers.
- Attackers can potentially execute commands or inject files through vulnerable public-facing applications without obtaining an SSH login.
- SSH authentication logs help identify remote access but cannot independently identify the source of every file modification.
- File metadata and SHA256 checksums help preserve investigation evidence.
- WAF protection, least-privilege permissions, secure uploads, and file integrity monitoring help reduce application-level security risks.
- Security hardening must be combined with incident investigation and recovery from a trusted state.
