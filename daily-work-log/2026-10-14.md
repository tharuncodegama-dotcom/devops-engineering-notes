### 2.6 Studied AWS VPC Architecture

Learned the purpose of a Virtual Private Cloud (VPC) and how it supports a multi-tier application deployment.

**VPC configuration:**

- VPC CIDR: `10.0.0.0/16`
- Frontend EC2 private IP: `10.0.1.17`
- Backend EC2 private IP: `10.0.2.43`
- Database private IP: `10.0.3.50`

**Key concepts learned:**

- VPC provides an isolated, configurable network in AWS.
- Subnets divide the VPC address range into smaller network segments.
- Route tables control where network traffic is directed.
- Internet gateways provide internet connectivity when routing and addressing are configured appropriately.
- Security groups control allowed inbound and outbound traffic.
- Private IP addresses support communication between resources over the private network.
- Public IP addresses provide internet reachability when the network and security configuration permits it.

**Application traffic flow:**

Browser → DNS → Frontend EC2/Nginx → Backend API → MySQL database.

The backend and database should be protected from unnecessary direct public access.

## 4. Key Learnings

1. An Elastic IP provides a stable public IPv4 address for an EC2 resource while it remains allocated and associated appropriately.
2. DNS maps a hostname to an IP address.
3. Security groups act as virtual firewalls for AWS resources.
4. HTTPS uses TLS to encrypt communication and authenticate the server's domain.
5. Certbot automates certificate issuance and can configure supported web servers.
6. HTTP status codes such as `200 OK` and `301 Moved Permanently` help verify application access and redirects.
7. A VPC provides network isolation and control over IP addressing, subnets, routing, and connectivity.
8. A multi-tier architecture separates frontend, backend, and database responsibilities.
