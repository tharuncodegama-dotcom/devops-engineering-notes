## 1. EST (Eficyent Secure Tunnel) – Technical Learning

Continued learning about Eficyent Secure Tunnel (EST), its architecture, security mechanisms, and DevOps responsibilities.

### What I learned

- EST is a security layer designed to protect communication between microservices in a distributed payment system.
- Understood how EST helps prevent unauthorized services from directly accessing sensitive microservices.
- Learned about the sidecar-agent architecture, where an EST agent runs alongside each application.
- Understood how local applications communicate with their EST agents and how agents communicate securely across servers using mTLS and signed request information.

### Nine security layers

1. Mutual TLS (mTLS) – Authenticates both communicating agents.
2. Topology allowlist – Restricts communication to approved service paths.
3. Ed25519 signatures – Provides cryptographic proof of request history.
4. Replay protection – Prevents previously captured requests from being reused.
5. Freshness validation – Validates request timestamps and hop timing.
6. Request commitment – Protects request body, path, and route from tampering.
7. Rate limiting – Controls excessive requests.
8. Body size and timeout limits – Protects against oversized requests and slow connections.
9. CA and certificate pinning – Restricts trust to approved certificate authorities and peers.

### Additional concepts

- mTLS
- SVID (Secure Verifiable Identity Document)
- Ed25519 digital signatures
- Nonce
- Replay protection
- Certificate pinning

### Communication topologies

- Linear topology: Services communicate in an expected sequence.
- Bouncing topology: A service can recheck another service's response before forwarding the request.
