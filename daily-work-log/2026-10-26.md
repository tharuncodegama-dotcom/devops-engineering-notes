## 3. Investigated the failed `bhimmarkets_backup` export

### Error encountered

The PostgreSQL export failed while reading compressed TimescaleDB data:

```text
ERROR: query failed: ERROR: chunk not found
DETAIL: relid: _timescaledb_internal._hyper_34_106_chunk
```

The dump also emitted a warning about circular foreign-key constraints on `continuous_agg`. The fatal error stopping the export was `chunk not found`.

### Diagnostics performed

- Checked PostgreSQL and TimescaleDB versions.
- Confirmed that `_timescaledb_internal._hyper_34_106_chunk` and `_timescaledb_internal.compress_hyper_35_139_chunk` physically existed in PostgreSQL's relation catalog.
- Found a compression-settings mapping between the two relations, but no matching row for the source relation in `_timescaledb_catalog.chunk`.
- Checked TimescaleDB job statistics. The Job History Log Retention Policy showed repeated failures; the diagnostic script reported 13 failed executions. This has not been established as the cause of the dump failure.
- Ran the TimescaleDB diagnostic SQL script. It exited with code `0` but did not repair the chunk issue.
- Identified 419 compression mappings without matching source-chunk catalog entries.
- Measured approximately 3,352 KB of associated compressed-relation storage and 0 bytes reported for the source relations.
- Checked all 419 compressed relations: `Checked: 419, nonempty: 0, failed: 0`.
- Checked all 419 corresponding source relations: `Checked: 419, nonempty: 0, failed: 0`.

### Current status

The large `bhimmarkets_backup` database has **not yet been successfully exported**. The identified source and compressed relations appear empty according to the checks performed, but this does not prove that a filtered dump will restore correctly or preserve all required data.

No source relations or internal catalog rows were deleted or modified during these checks.

## Key learnings

- Verify backup archives after creation and again after transfer. A successful ZIP integrity test does not by itself guarantee application-level or database-level completeness.
- Use `pg_dump` and `pg_restore` for PostgreSQL logical migration rather than copying a live PostgreSQL data directory directly.
- TimescaleDB compressed hypertables depend on extension-managed metadata. An internal `chunk not found` error needs careful investigation; manually deleting or modifying internal catalog objects is unsafe.
- A diagnostic script can execute successfully while still reporting database maintenance warnings.
- Keep `.env` files and SQL dumps private. The `pay-backup` ZIP is not encrypted.
