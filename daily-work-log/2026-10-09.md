## 1. Objective

Practice Linux memory management and AWS storage administration on an Ubuntu EC2 instance. Configure swap space, attach EBS volumes, implement Logical Volume Management (LVM), and verify filesystem persistence and expansion.

## 2. Work Completed

### 2.1 Configured Swap Memory

* Checked the available RAM and swap memory on the EC2 instance.
* Created a 2 GiB swap file to provide additional virtual memory.
* Set the correct file permissions and initialized the swap file.
* Enabled swap space using `swapon`.
* Updated `/etc/fstab` to enable swap automatically after reboot.
* Verified swap availability using `free -h` and `swapon --show`.

**Commands used:**

```bash
free -h
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
swapon --show
```

Persistent configuration in `/etc/fstab`:

```text
/swapfile none swap sw 0 0
```

### 2.2 Attached AWS EBS Volumes

* Worked with an Ubuntu EC2 instance using its existing system disk and two additional 2 GiB EBS volumes.
* Identified the available block devices using Linux storage commands.
* Distinguished the operating system disk from the additional EBS volumes before making storage changes.
* Used `/dev/nvme1n1` and `/dev/nvme2n1` as the additional EBS devices.

**Commands used:**

```bash
lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINTS
sudo lsblk -f
```

### 2.3 Created an LVM Storage Configuration

* Initialized the first EBS volume as an LVM Physical Volume (PV).
* Created a Volume Group (VG) named `devops_vg`.
* Created a Logical Volume (LV) named `data_lv` with an initial size of 1 GiB.
* Formatted the logical volume with the ext4 filesystem.
* Created `/data` and mounted the logical volume there.
* Created a test file to validate storage functionality.

**Commands used:**

```bash
sudo pvcreate /dev/nvme1n1
sudo vgcreate devops_vg /dev/nvme1n1
sudo lvcreate -L 1G -n data_lv devops_vg

sudo mkfs.ext4 /dev/devops_vg/data_lv
sudo mkdir -p /data
sudo mount /dev/devops_vg/data_lv /data

echo "LVM storage test" | sudo tee /data/test.txt
cat /data/test.txt
```

### 2.4 Configured Persistent Mounting

* Retrieved the filesystem UUID for the logical volume.
* Added an entry to `/etc/fstab` to mount the ext4 filesystem automatically.
* Rebooted and reconnected to the EC2 instance to verify that `/data` was mounted and the test file remained available.

**Configuration used:**

```text
UUID=da1ed17c-ff67-45e6-a1ae-0b5c815a6214 /data ext4 defaults,nofail 0 2
```

**Verification commands:**

```bash
findmnt /data
df -hT /data
cat /data/test.txt
```

### 2.5 Extended the Logical Volume

* Increased the logical volume from 1 GiB to 1.5 GiB.
* Expanded the ext4 filesystem to use the additional capacity.
* Verified the new filesystem size.

**Commands used:**

```bash
sudo lvextend -L 1.5G /dev/devops_vg/data_lv
sudo resize2fs /dev/devops_vg/data_lv
df -hT /data
```

### 2.6 Added a Second EBS Volume to LVM

* Initialized the second 2 GiB EBS volume as a Physical Volume.
* Extended the existing `devops_vg` Volume Group with the second EBS volume.
* Expanded `data_lv` to 3 GiB.
* Resized the ext4 filesystem to use the expanded logical volume.
* Verified the physical volumes, volume group, logical volume, and mounted filesystem.

**Commands used:**

```bash
sudo pvcreate /dev/nvme2n1
sudo vgextend devops_vg /dev/nvme2n1

sudo lvextend -L 3G /dev/devops_vg/data_lv
sudo resize2fs /dev/devops_vg/data_lv

sudo pvs
sudo vgs
sudo lvs
df -hT /data
```

## 4. Key Learnings

* Swap provides additional virtual memory when physical RAM is under pressure, although it is slower than RAM.
* EBS provides persistent block storage for EC2 instances.
* A Physical Volume is a disk or partition prepared for LVM.
* A Volume Group combines storage capacity from one or more Physical Volumes.
* A Logical Volume provides a flexible block device that can be formatted and mounted.
* `lvextend` increases logical volume capacity, while `resize2fs` expands an ext4 filesystem.
* `/etc/fstab` supports persistent mounting across reboots.
* Storage changes must be verified at the block-device, LVM, filesystem, and mount levels.

## 5. Important Safety Notes

* Avoid modifying the EC2 root disk when practicing additional storage configuration.
* Validate device names before running `pvcreate`, `mkfs`, or other destructive commands.
* The two additional EBS volumes are part of `devops_vg`; do not detach or delete them without a migration and recovery plan.
* Review `/etc/fstab` carefully before rebooting to prevent mount configuration issues.
